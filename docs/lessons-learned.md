## P9【S+】北向上实为南向上——"方向相反"族谱的终章

- **症状**：0096 北向上模式车标与移动方向恒相反；HeadingUp 一致正确。
- **时长**：当日诊断 ~3h。但它是**七次发作族谱**（09-09 → 09-17）的最后一次：KITTI yaw → 航向公式 → 航向源 → 引擎定律推论，跨四个层、五个会话。
- **代码量**：**2 行**（heading 0→180 ×2 处）+ ~30 行测试。
- **根因**：引擎实测定律 R = 180° − h ⇒ `heading:0` 渲染南向上。09-16 已实测出定律本身，但其推论"h=0=北向上"从未被验证——而地图倒置被道路网近似对称性伪装，无人读街道名。
- **为什么难**（四个结构性原因，详见 findings「北向上实为南向上」节）：
  1. **1-bit 症状 × 五层符号系统**：数据约定/数学/公式/CSS/引擎，任何一层翻转都是同一症状；
  2. **抵消性错误**：地图翻转 180° × 公式多加 180° = heading-up 完美正确——每修好一层就暴露下一层，洋葱式复发；
  3. **验证通道全失效**：视觉模型 ±50° 自相矛盾、无头无 WebGL、有头探针 Tangram 场景也起不来、互相关探针两次翻符号；
  4. **验证了错误命题**："A/B diff=0"被记录为"北向上已验证"——它只证两条路径渲染相等，两个南向上同样 diff=0。
- **怎么破**：用户 2-bit 判别观察（北向上反/heading-up 对）+ 代数强制解 + 逐层排除（离线数学杀切线、代码审查杀底图/祖先链）+ **geoToScreen 数值探针**（运行时包装 H.Map 捕获实例，不依赖渲染，0/90/180/270 × N/E/S/W 十六点直接测出引擎传递函数）。
- **一句话教训**：**多层旋转变换的总符号是各层符号之积——某配置"看起来对"可能恰是两个错误相乘为正。必须对每层单独测符号，而不是只测合成结果。**

## P5【S−】车标抖动三因叠加

- **症状**：回放中车标抖动/闪跳/脱路；baseline（60fps 浮点）与当前树（10Hz 门控）都抖——排除渲染节奏假设。
- **时长**：09-15 全天 + 次日收尾。含 **P2 纯几何方案三连败**（粘滞/到访序/单调弧长均被量化否决：p90 1.4–3.4m、60–96 次杂步）。
- **代码量**：~650 行（matchedTrack.ts 240 + 测试 157 + derive/types/fixtureStore/App/MapView/playback 接线）。
- **根因（三因叠加，互相伪装）**：① MM 响应是地理不相连碎片（断口最大 73m，拼接序≠驾驶序），逐帧全局最近投影单帧闪跳 5–73m；② DR dispSpeed 门控在两种速度源间切换 → 步长 CV 45%；③ 引擎 marker 与相机双路径相位差（用户判别"地图平滑、车标独抖"一击定位）。
- **过程要点**：先量化再动手（垂足闪跳/DR 步伐 CV/静止期 0.11m 步/rAF p50 三条证据链）；P2 三连败换来核心教训"**几何连续 ≠ 运动学连续**"；最终解 = 运动学门控序列匹配（预测+拒绝门+弱锚定+重绑 dwell+掠过摊平）+ 车标改钉相机中心的 DOM 叠层（结构性消灭双路径）。
- **附带小修**：叠层锚点 50%→67%（脱路 150px，134% 宿主高 → 相机中心在 67%）；图标异步解码改 `<img>` 内联；合成测试数据物理自洽（0.001°/帧被滤波器当 730m/s 拒绝）；长 HMR 会话 WebGL 上下文耗尽白屏（勿误判回归，pristine 对照）。
- **一句话教训**：**多因症状必须先建立量化证据链再分因治理；被否决的方案族（纯几何连续性）要记录否决理由，防止三次踩同一坑。**

## P7【A】heading-up 圆圈/道路名抖动（含两次回归）

- **症状**：车头向上播放中 GNSS 圆圈全体微抖、0096 >38s 道路名微抖，暂停即止。
- **时长**：09-16 上午半天（含两次回归修复）。
- **代码量**：~60 行净改 + 测试。
- **根因**：heading-up 用「外层 CSS rotate+2.3×scale 宿主」实现，引擎按未旋转坐标系整像素重定位 DOM marker/矢量标签——双路径互搏被放大（与 P5③ 同族）。修复 = 删 CSS，改引擎原生 setLookAtData 逐帧驱动。
- **回归 1（勿重蹈）**：lookAtData 平移字段误用 `center`，被引擎**静默忽略** → 车标原地转圈。教训：v3.1 契约字段是 `position`（H.geo.Point）；**假 H 测试当时与代码同错了假设——测试必须断言真实契约字段**。
- **回归 2（勿重蹈）**：航向公式按被污染的 0093 IMU 基准拟合 → 错误定律 → 用户实测否决。教训：**校准基准必须先证明纯净**。
- **一句话教训**：**引擎/框架的"静默忽略"是回归温床——契约字段要进测试；替换渲染路径时旧路径的隐性假设全部要重新验证。**

## P8【A】航向源绑路（IMU 漂移确诊）

- **症状**：用户再报两模式航向与行驶方向相反/差 60°（0096）。
- **时长**：09-16 午后半天。
- **代码量**：~40 行（trackTangentBearing + carState 航向源改造）。
- **根因**：0093 数据集 IMU headingDeg 漂移 4→180°（"真值不可信"）；0096 IMU↔位移吻合 0.1°。修复 = 航向源改轨道切线（与位置同源，构造性贴路）+ 位移方位回退。
- **过程要点**：三轮用户判别实验拟合引擎定律（传 B→正下；传 360−B→差 60°=2B−180；传 B+180→朝上）——**每轮消掉一半假设空间**；旋转互相关探针两次推反符号 → 确立"仪器只做 DOM/数值层，方向类结论必须用户目视终验"。
- **一句话教训**：**传感器/数据源退化要先定量判别（漂移曲线）再决定采信策略；判别实验设计的目标是信息量，不是数量。**

## P1【B】KITTI yaw 约定——族谱第一章

- **症状**：车标航向恒偏（0033 偏 15.6°、0011 偏 59.5°）。
- **时长**：09-09 半天内。**代码量**：34+/11−。
- **根因**：`headingDeg` 实为 KITTI oxts yaw（0=东、逆时针），被当罗盘角（0=北、顺时针）消费。
- **为什么这次干净**：有对照通道——坐标反算真航向 vs 图标航向，两轨迹 100% 点位误差 ≤5°，一次锁定公式 `compass=(90−yaw)%360`。
- **一句话教训**：**外部数据字段命名 ≠ 语义；有 ground-truth 反算通道时，约定类错误半小时可杀。**

## 09-30 ~ 10-07 会话：暂停态 / 街道名抖动族

### P13【C+】播放结束后车标浮在下 1/3 处不动

- **症状**：Demo 播放暂停/结束后移图缩放，车标停在画面下 1/3 不在真实位置。
- **根因**：DOM 叠层是屏幕空间元素，只在相机锁定跟随时与地理坐标对齐。暂停后相机不跟随但叠层还在。
- **修复**：新增 `playing` prop——播放中=DOM 叠层+锁定跟随，暂停/结束=HERE marker+不锁定。~50 行，~30min。
- **教训**：屏幕空间叠层 vs 地理空间元素是两种渲染范式，切换时机要显式驱动。

### P14【C】进入 Demo 未播放车标不可见

- **症状**：点 Demo tab（未播放）地图停在全轨迹视野，车标看不到。
- **根因**：P13 副作用——`!playing` 分支相机 effect return 了，没定位到 carPos=0。
- **修复**：`!playing` 分支也执行 `setLookAtData({ position })` + zoom 17。~10 行，~15min。
- **教训**：引入状态分支时检查每个分支的"初始进入"路径。

### P15【C+】播放时街道名抖动——两步 setLookAtData 双重重定位

- **症状**：Demo 播放中地图街道名（矢量标签）微抖；暂停不抖。
- **根因**：播放态每帧调两次 `setLookAtData`（先定位车标，再 `screenToGeo` 偏移到下 1/3）→ 引擎每帧双重视口更新 → 标签整像素重定位两次 → 抖动。
- **修复**：恢复 134% 宿主高方案——宿主 div 高 134%，相机中心天然在容器 67%，单步 `setLookAtData` 即达导航布局，无需 `screenToGeo` 第二步。~20 行净改，~1h。
- **教训**：引擎每帧的 `setLookAtData` 调用次数要最小化——两次调用即使参数连续，引擎内部的视口更新/像素对齐也产生亚像素差异，放大为可见抖动。134% 宿主高是 HERE 3.1 经典导航布局技巧：用 DOM 尺寸偏移相机中心，避免代码层面的二次位置修正。
- **与前序问题的关系**：P5③（引擎 marker vs 相机双路径）、P7（CSS rotate+scale 放大整像素重定位）、P15（同管线两次调用）三抖动同族——根因都是"引擎多路径/多调用的亚像素差异被放大"。P5③ 消灭于 DOM 叠层替代引擎 marker，P7 消灭于引擎原生航向替代 CSS 旋转，P15 消灭于 134% 宿主高替代两步 setLookAtData——**每次都是减少引擎更新次数/路径**。

### P16【C+】分析模式视野不完整 + 播放缩放限制

- **症状**：Analysis 模式下轨迹起点/终点/DR 点贴边甚至超出视野；播放时无法缩小到 17 以下。
- **根因（三因叠加）**：① 宿主高 134% 在 Analysis 模式也生效（引擎以为视口大 34%，底部被裁）；② bounds 只算 trace+derived+drPath（gnssPath/carTrace/carTrack 远点不纳入）；③ zoom 下限 17 是遗留补偿（134% 方案下不需要）。
- **修复**：宿主高条件化（Demo 134% / Analysis 100%）+ bounds 纳入全部 6 层 + 去掉 zoom 下限 + bounds 四周扩 8% 余量。~18 行，~30min。
- **教训**：为一个模式设计的全局参数（134% 宿主高 / zoom 下限）在另一个模式下会变成 bug——模式特有参数要条件化，不能无差别应用。bounds 计算要覆盖全部图层，否则任一图层的远点都会被初始视野裁剪。

### P17【C+】播放中滚轮缩放失效（10-20）

- **症状**：Demo 播放中滚轮缩放几乎无效（8 格 +0.27）；暂停正常（+3.6）。线上报障，本地复现。
- **根因**：播放跟随的每帧 `setLookAtData({position,heading}, false)`（60Hz）打断原生 `Behavior.WHEELZOOM` 的动画式缩放——动画进程被每帧视模型重置丢弃。zoom 值不丢（P16 不传 zoom 已修 snap-back），但动画永不完结。P16 同族残余：当时只验了调用参数（不传 zoom），没验进程（动画走不完）。
- **修复**：播放中 `disable(WHEELZOOM)` + 自定义 wheel 监听走无动画 `setZoom(±0.5, animate=false)` 同步步进；暂停 `enable` 还原原生动画缩放。~15 行，~2h（Playwright 探针定量：修复后播放 +3.87 / 暂停 +5.0，dev 与线上逐项一致）。
- **教训**：**「值正确 ≠ 交互健康」**——引擎动画由异步进程执行，每帧写视模型的调用会把一切在途动画归零。修复值类症状后必须对同一交互做端到端数值验收（合成 N 格输入 → 读 `getLookAtData().zoom` 真值），不能只停在调用参数断言。
- **防线**：`mapview.test.tsx` 播放中 wheel → setZoom 步进（±0.5，animate=false）+ Behavior disable/enable 随 playing 切换，3 个接线测试。

## 横向元教训（跨问题模式）

1. **挑战与代码量负相关于诊断难度**。本工程两个极值：P9（2 行/三天/七次发作）vs P10（400 行/一天/一次过）。排期时"看起来简单"的症状（1-bit 布尔类）恰恰要预留最长的诊断预算。
2. **一个症状 ≠ 一个 bug**。七次"方向相反"是四个层的四次不同故障 + 三次修复的副产物。复发不一定是"没修好"，可能是洋葱剥到下一层——每次复发都要重新走根因流程，禁用"上次就是这么修的"记忆捷径。
3. **验证通道的可信度要先于验证本身被验证**。本工程的通道淘汰史：视觉模型（±50°，禁）→ 截图（白板幻觉，加 ≥300KB 门槛）→ 无头浏览器（无 WebGL，禁）→ 有头探针（Tangram 场景挂，仅 DOM 几何可用）→ **geoToScreen 数值通道（终器）**。仪器建设花的每一分钟都在后续问题里连续复利。
4. **验证结论不得强于实验实际证明的命题**。"diff=0"≠"北向上"；"heading-up 对"≠"方向族关闭"。写结论时把实验证明了什么和推断了什么分开记录。
5. **校准/对照的基准要先证纯净**。0093 漂移 IMU 作为基准产出了错误定律，成本是一整个用户往返轮次。
6. **外部黑盒与文档矛盾时，测传递函数、钉回归测试、停止再读文档**。R=180−h 现在是 mapview.test.tsx 里的硬编码契约（判别性取值 yaw=180）。
7. **角度/方向代码没有直觉护栏**。三次仪器或助手翻符号（互相关×2、diff 函数 `180−d` 反向包装）——任何角差/方位助手必须先用手算样例（如 214.5 vs 214.5 应得 0）自证再用。
8. **TDD 的判别性取值**：yaw=90（compass=0）在两种公式下同值 → 假绿；yaw=180 才能区分 270 vs 90。写测试先检查取值能否区分实现空间。
9. **用户判别实验是最便宜的高信息通道**："地图动还是车标动"（P5）、"哪一模式反"（P9）各一击定位层级。设计成 2-bit 问题（是/否 × 两模式），一次消一半假设空间。
10. **定性结论绑定环境前提**（P11）：同款报错在 StrictMode dev 是噪声、在探针 profile 是真死。
